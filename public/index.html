01 / THE METHOD

FROM REPORT
TO RECEIPT.

Less “looks legit to me.” More “here’s exactly what happened.”

01

TAKE THE CLAIM.

Start with a GitHub repository. ClaimSentry collects open issues and pull requests for triage.

02

RUN THE TEST.

Scan real symbols, execute minimal reproductions in a restricted sandbox, and check changed-line coverage.

03

SHOW THE PROOF.

Get a verdict backed by concrete artifacts: traces, exit codes, file locations, and coverage data.

02 / THE TOOLKIT

FOUR WAYS TO
FIND THE TRUTH.

Different claims need different tests. One place to inspect the evidence.

Verifier A / Bug reports↳

REPRODUCE IT.

Run a minimal reproduction in the sandbox. Keep the exception, stdout, and exit code instead of a hunch.

Verifier B / Security claims⌕

FIND THE SYMBOL.

Audit the codebase to check whether a claimed vulnerable function or component actually exists.

Verifier C / Pull requests%

CHECK THE DIFF.

Compare modified lines with test coverage to see what a pull request really exercises.

Verifier D / Screenshots & video▣

READ THE SIGNAL.

Extract text from screenshots and video keyframes, then compare the clues with repository code.

03 / THE NON-NEGOTIABLES
